## 1. 项目目标（Objectives）

### 1.1 总目标

构建一个**可重复、可评估、可迭代**的自动对接系统，使载体在仿真环境中稳定完成从搜索/接近到机械或几何对接的全流程任务。

### 1.2 细化目标

- 任务成功性：提高对接成功率，降低超时与碰撞终止比例。
- 控制稳定性：在接近末端抑制振荡，控制接触瞬间冲击。
- 安全性：通过速度、姿态、距离和时间约束，降低失控风险。
- 工程可复现：实验脚本一键多轮运行，输出可比较指标。
- 可扩展性：支持后续感知、控制、规划模块替换而不重写整条链路。

---

## 2. 系统方法总览（Method Overview）

对接方法采用“**分阶段状态机 + 相对位姿闭环控制 + 末端速度约束 + 安全守护逻辑**”。

从工程视角看，它不是单一控制器，而是一个层级式系统：

- 任务层（Mission/State Machine）：决定当前处于哪一个 docking 阶段。
- 制导层（Guidance）：生成当前位置到目标位姿的参考轨迹或参考速度。
- 控制层（Control）：将参考量转换为姿态/速度/推力指令。
- 安全层（Safety Guard）：持续检查碰撞风险、速度上限、超时、状态异常。
- 评估层（Evaluation）：记录与汇总指标，用于回归与参数优化。

## 3. 对接方法（核心）

## 3.1 坐标系与误差定义

为避免“看上去成功、实际偏置很大”的问题，对接系统先明确误差定义。

- 世界坐标系 `W`：仿真全局坐标。
- 机体系 `B`：载体本体坐标。
- 对接口坐标系 `D`：目标 docking port 坐标。

常用误差量：

- 位置误差：`e_p = p_D - p_B`（可在 `W` 或 `D` 中表达）
- 速度误差：`e_v = v_D - v_B`（若目标静止则 `e_v = -v_B`）
- 姿态误差：`e_R` 或 yaw/pitch/roll 误差向量
- 轴向误差：沿 docking 轴方向的投影误差（决定接触前推进）
- 横向误差：垂直 docking 轴平面内误差（决定是否允许进入末端）

工程上最关键的是将误差拆成“轴向 + 横向 + 姿态”三类，因为它直接对应分阶段控制权重。

## 3.2 分阶段状态机（State Machine）

典型状态机如下：

1. `SEARCH/INIT`：初始化与目标锁定。
2. `FAR_APPROACH`：远距离接近，强调收敛速度与大范围稳定。
3. `ALIGNMENT`：中近距离姿态/横向对齐，降低轴外误差。
4. `FINAL_APPROACH`：末端慢速推进，严格速度和姿态门限。
5. `CONTACT_LATCH`：接触判定与锁定确认。
6. `DOCKED`：任务完成。
7. `ABORT/RETREAT`：任意阶段触发安全回退。

每个状态都有进入条件、保持条件、退出条件。  
如果没有显式退出条件，系统常会出现“在末端来回抖动”或“反复触发接触失败”。

## 3.3 制导策略（Guidance）

制导层目标是把“误差”转成“可控、可跟踪”的参考量。

常见实现：

- 位置型制导：给出参考位置 `p_ref(t)` + 速度前馈 `v_ff(t)`。
- 速度型制导：直接给出参考速度 `v_ref`。
- 混合型：远端位置制导，近端速度制导。

对接任务中常用混合策略：

- 远端：以位置误差为主，快速收敛到对接走廊。
- 近端：以速度和姿态约束为主，避免接触冲击。

一个实用形式：

`v_ref = sat( Kp * e_p + Kv * e_v + v_ff , v_max(stage) )`

其中 `v_max(stage)` 随阶段收紧：

- `FAR_APPROACH`：较大上限，优先效率。
- `ALIGNMENT`：中等上限，优先对齐。
- `FINAL_APPROACH`：严格小上限，优先安全与接触成功率。

## 3.4 控制策略（Control）

控制层把 `v_ref`/`p_ref` 变成飞控可执行命令（姿态、角速度或推力）。

典型分解：

- 平移控制：跟踪 `p_ref` 或 `v_ref`，抑制位置/速度误差。
- 姿态控制：在接近末端将对接轴对准目标法向或导向轴。
- 速率限制：限制加速度、jerk、角速度，避免末端振荡。

末端阶段推荐控制特性：

- 降低横向通道增益，减少轴外来回修正。
- 强化姿态阻尼，防止接触前“点头/摇头”。
- 对轴向推进设置单调性（避免前后反复）。

## 3.5 末端速度约束（关键机制）

你当前流程里出现了 `CARRIER_TRACKING_SPEED_LIMIT` 这类参数，说明项目已采用速度约束机制。该机制通常是对接成功率的核心提升点。

可执行做法：

- 速度门限分段：
  - 远端上限 `v_far`
  - 中端上限 `v_mid`
  - 近端上限 `v_near`（最小）
- 距离相关限幅：`v_max(d)` 随目标距离 `d` 单调下降。
- 接触前窗：进入接触窗（例如 `d < d_contact_window`）后只允许低速推进。
- 姿态联动限速：姿态误差超阈值时自动降低推进速度。

这使系统从“追踪误差最小化”转为“追踪 + 安全接触”的多目标平衡。

## 3.6 对接判定与锁定（Contact & Latch）

对接成功不应只靠“距离小于阈值”单一判据，建议多条件联合：

- 距离阈值：`||e_p|| < eps_p`
- 姿态阈值：`||e_R|| < eps_R`
- 速度阈值：`||v_rel|| < eps_v`
- 稳态持续时间：满足以上条件持续 `T_hold`

成功事件应带时间戳和状态快照，便于回放审计。

## 3.7 失败检测与回退（Abort / Retreat）

常见失败触发：

- 超时：某状态持续超过 `T_state_max`
- 偏航过大：姿态误差超过硬阈值
- 速度违规：近端阶段速度连续超限
- 安全距离违规：触发碰撞风险条件

回退逻辑建议：

- 先退出接触窗并恢复安全距离。
- 重新进入 `ALIGNMENT` 而非直接从 `FINAL_APPROACH` 重试。
- 记录失败类别，避免“黑盒失败”。

## 3.8 方法伪代码（便于实现对照）

```text
state = INIT
while not done:
  obs = get_relative_pose_velocity()
  safety_check(obs)

  switch state:
    INIT:
      if target_locked: state = FAR_APPROACH

    FAR_APPROACH:
      v_ref = guidance_far(obs)
      u = control(v_ref)
      if in_alignment_zone(obs): state = ALIGNMENT
      if unsafe_or_timeout: state = ABORT

    ALIGNMENT:
      v_ref = guidance_align(obs)  # tighten lateral and attitude
      u = control(v_ref)
      if aligned_and_close(obs): state = FINAL_APPROACH
      if unsafe_or_timeout: state = ABORT

    FINAL_APPROACH:
      v_ref = guidance_final(obs)  # strict speed limits
      u = control(v_ref)
      if contact_candidate(obs): state = CONTACT_LATCH
      if unsafe_or_timeout: state = ABORT

    CONTACT_LATCH:
      if stable_contact_for_hold_time(obs): state = DOCKED
      elif unstable_contact_or_timeout: state = ABORT

    ABORT:
      execute_retreat()
      if reattempt_allowed: state = ALIGNMENT
      else: done = true

    DOCKED:
      done = true
```

## 4. 实验与评估方法（How Results Are Produced）

## 4.1 批量实验机制

根据你现有流程，项目已通过脚本进行多轮实验。标准化流程应包含：

- 固定随机种子组（可复现实验）。
- 指定运行轮次 `N`（例如 5/20/100）。
- 每轮输出统一日志结构（CSV/JSON）。
- 实验后自动汇总统计表。

## 4.2 推荐核心指标

- 成功率：`success / total`
- 平均对接时间：`mean(T_dock)`
- 末端接触相对速度：`v_contact`
- 姿态误差统计：均值/95分位
- 失败类别占比：超时、越界、接触失败等
- 稳定性指标：不同初始条件下方差

## 4.3 结果解释逻辑

评估不只看“能否成功”，还看：

- 成功是否依赖单一参数窗口（鲁棒性差）。
- 成功时是否伴随高冲击接触（安全性不足）。
- 失败是否可归因（可维护性）。

## 6. 未来改进（Improvement Roadmap）

## 6.1 方法层改进（优先）

- 建立分阶段参数表，避免参数散落在脚本和代码中。
- 引入距离-速度自适应曲线 `v_max(d)`，替代固定常数限速。
- 引入姿态误差耦合限速：`v_max = f(d, e_R)`。
- 对 `FINAL_APPROACH` 使用更严格的抗抖策略（低通/阻尼/迟滞切换）。

## 6.2 工程层改进

- 自动输出 run-level + aggregate-level 报告。
- 增加失败回放索引（按失败类别跳转）。
- 加入回归基线门槛：成功率、接触速度、超时率。

## 6.3 评估层改进

- 扩展扰动集：初始位姿、传感噪声、通信延迟、动力学偏差。
- 增加统计显著性比较（A/B 参数组）。
- 强化 95/99 分位指标，避免只看平均值。

## 7. 建议的“方法参数表”模板

| 参数 | 含义 | 建议做法 |
|---|---|---|
| `v_far` | 远端最大速度 | 保证效率，不触发大姿态摆动 |
| `v_mid` | 中端最大速度 | 折中效率与对齐稳定 |
| `v_near` | 近端最大速度 | 严格小值，保障接触安全 |
| `eps_align_pos` | 进入末端前横向误差阈值 | 过大导致擦碰，过小导致难进入 |
| `eps_align_att` | 姿态误差阈值 | 与机械容差一致 |
| `eps_contact_v` | 接触速度阈值 | 安全关键参数 |
| `T_hold` | 接触稳定保持时间 | 防误判短时接触 |
| `T_state_max` | 状态超时阈值 | 防止卡死 |
